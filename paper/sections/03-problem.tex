\section{Problem Formulation}\label{sec:problem}

% --- Paragraph 1: setting and notation (v2, reviewed 2026-11-06) ---
% Note: "LLM" must be spelled out as "large language model (LLM)" at first use in the Introduction.
\textit{Setting.} A single vehicle is executing a route. At the current time $t_0$, its plan $P$
consists of the fixed, already-served stops and the remaining stops in their planned order, each with a scheduled arrival time.
A dispatcher issues a natural-language request $q$ to change $P$. An LLM
translates $q$ into an edit $\hat{e} = \mathrm{LLM}(P, q)$, a set of one or more typed operations,
such as a time window, a stop removal, or a precedence constraint (Section~\ref{sec:method}). We
write $\hat{c}$ for its operation type, with multi-operation edits forming one compound type. A
solver then re-optimizes the remaining stops under the edit and returns
$\hat{P} = \mathrm{Solve}(P, \hat{e})$. For evaluation, each request also has a gold edit $e^\star$
of operation type $c$ and the gold plan $P^\star = \mathrm{Solve}(P, e^\star)$, computed with the
same solver configuration. Neither $e^\star$ nor $P^\star$ is available at deployment.

% --- Paragraph 2: plan-level harm (v2, reviewed 2026-11-06; spec 09) ---
\textit{Harm.} We judge an edit by the plan it produces instead of its text.
Let $V(\hat{P}, e^\star)$ be the largest violation, in minutes, of any constraint of $e^\star$ in $\hat{P}$, such as how early a stop is served before its new window opens.
Let $S(\cdot)$ be the set of stops a plan visits and $\mathrm{cost}(\cdot)$ the travel time plus a penalty on minutes late
against time windows.
The executed edit is harmful, $h = 1$, if
\begin{equation}\label{eq:harm}
  V(\hat{P}, e^\star) > \tau \;\lor\; S(\hat{P}) \neq S(P^\star) \;\lor\;
  \mathrm{cost}(\hat{P}) - \mathrm{cost}(P^\star) > \varepsilon ,
\end{equation}
and $h = 0$ otherwise, with tolerance $\tau = 1$~min and
$\varepsilon = \max\{5~\text{min},\, 0.02\,\mathrm{cost}(P^\star)\}$. The three terms catch an
unmet request, a dropped or wrongly kept stop, and an unrequested detour. A wrong edit triggering none of them is a harmless error.
If $\hat{e}$ cannot be parsed or the solver finds it infeasible,
it is \emph{non-executable} and is never executed. We mark this with $x = 0$ ($x = 1$ otherwise);
its harm $h$ is then undefined, and we take $x\,h = 0$. A harmful edit with
$\hat{P} = P$ is a \emph{non-binding} error: the wrong constraint already holds on the current plan,
so the solver changes nothing and reports success.

% --- Paragraph 3: decision rule and risk (v3, 2026-11-06; spec 12 §2) ---
% The calibration algorithm (formula for \hat\lambda, threshold grid) goes in Section IV, not here.
\textit{Decision rule and risk.} A risk score $s$ is computed from $P$, $q$, the LLM outputs, and
solver feedback, without $e^\star$ (Section~\ref{sec:method}); a higher $s$ means a more suspicious edit. Given a
threshold $\lambda$, the system executes $\hat{P}$ if $x = 1$ and $s \le \lambda$, and otherwise
defers the request to the dispatcher. Only an executed harmful edit incurs a loss,
$L(\lambda) = x\,h\,\mathbf{1}\{s \le \lambda\}$. As in CORA~\cite{feng2026cora}, we require the
joint risk
\begin{equation}\label{eq:joint}
  R(\lambda) = \mathbb{E}\left[L(\lambda)\right] \le \alpha
\end{equation}
for a chosen level $\alpha$ while executing as many requests as possible. Since $L$ is bounded by $1$ and non-decreasing in $\lambda$,
conformal risk control (CRC)~\cite[Thm.~1]{angelopoulos2024crc}, applied to $-\lambda$,
selects $\hat{\lambda}$ on calibration requests such that $\mathbb{E}[L(\hat{\lambda})] \le \alpha$.
The expectation also covers the calibration set, and the bound requires calibration and test
requests to be exchangeable. Setting $\lambda = -\infty$ defers every request at zero loss, so a
valid threshold always exists.
A single threshold can still hide violations
concentrated in rare operation types~\cite{rahman2026rolestratified}, so we also calibrate one
threshold $\lambda_{\hat{c}}$ per LLM-edit type $\hat{c}$ (known at deployment) and require
$\mathbb{E}[L(\lambda_{\hat{c}}) \mid \hat{c}] \le \alpha$ for every $\hat{c}$. The conditional risk
$\Pr(h = 1 \mid \text{executed})$ is not monotone in $\lambda$, so the guarantee of CRC does not
extend to it~\cite[Prop.~1]{angelopoulos2024crc}.

% --- Paragraph 4: maximum-coverage bound (v2, 2026-11-06; spec 12 §2.4, spec 13 §14) ---
\textit{Coverage bound.} Coverage is the share of requests executed,
$\mathrm{cov}(\lambda) = \mathbb{E}[x\,\mathbf{1}\{s \le \lambda\}]$. Let $\mu = \mathbb{E}[x\,h]$
be the base harm rate when every executable edit is executed, and $\pi = \Pr(x = 0)$ the share of
non-executable edits, which are always deferred. If $\mu \le \alpha$, executing everything already
satisfies (\ref{eq:joint}) and there is nothing to control. Otherwise, at most a fraction $\alpha$ of
requests may end in an executed harmful edit, so even an oracle score that defers only harmful
edits reaches at most
\begin{equation}\label{eq:covmax}
  \mathrm{cov}_{\max} = 1 - \pi - \max\{0,\, \mu - \alpha\}.
\end{equation}
We use (\ref{eq:covmax}) as the reference for every risk--coverage result.
